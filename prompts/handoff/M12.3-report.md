# M12.3 — Intent-aware operational chat and evidence-bound visualization

## Durum

DONE

## Sonuç

OTP Sentinel artık tek bir composer üzerinden üç ayrı kullanıcı görünür sonuç üretir:
toolsuz doğal `CHAT`, toolsuz tek soruluk `CLARIFICATION` ve mevcut güvenli agentic
pipeline'a bağlanan `INVESTIGATION`. `AUTO|CHAT|INVESTIGATION` interaction mode'u
`QUICK|THOROUGH` investigation mode'undan ayrıdır. Yeni sözleşme
`POST /api/v1/chat/messages` endpoint'inde sunulur; eski investigation endpoint'leri
geriye uyumlu kalır.

Production intent seçimi seçili allowlist modeliyle structured-output LLM çağrısıdır;
Java keyword/regex intent engine eklenmedi. Java katmanı enum, confidence, plain-text,
PII, model allowlist, time-window ve failure sözleşmelerini fail-closed doğrular. AUTO
route bozuksa en fazla bir repair denemesi yapılır ve ardından
`502 INTENT_ROUTING_FAILED` döner. CHAT ve CLARIFICATION AiServices örneklerine hiçbir
tool bağlanmaz; semantic session context investigation tool memory'sinden ayrı, turn ve
LRU sınırları olan in-memory store'da tutulur.

Investigation modeli artık yalnız dar bir `VisualizationProposal` şeması önerebilir.
Java validator bilinen evidence ID, canonical numeric value, uyumlu unit, bilinen chart
type ve boyut sınırlarını doğrular. Geçersiz grafik analiz sonucunu bozmaz; grafik düşer
ve `VISUALIZATION_REJECTED` warning'i eklenir. Kabul edilen canonical grafikler V7
Flyway migrasyonu ile investigation snapshot'ına persist edilir ve POST/GET sonucunda
aynı biçimde döner.

Frontend local conversation formatını v2'ye taşıdı ve eski kayıtları güvenli biçimde
migrate eder. Normal chat sade mesaj olarak, clarification tek takip sorusu olarak,
investigation ise evidence/hipotez/RAG/grafik/onay yoğunluğunda render edilir. Grafik
renderer yalnız typed `LINE|BAR|GROUPED_BAR|GAUGE|TABLE` şemasını map eder; modelden
arbitrary Recharts config, HTML, JavaScript veya expression çalıştırılmaz.
